APK 裡有什麼

一支 APK 說到底就是一個改了副檔名的 ZIP。它必須裝著哪些檔案、每個檔案是誰、 又是被哪一隻工具在打包流程的哪一步放進去的 —— 這裡用 SVG + SMIL 動畫拆開來看。 所有數字都取自本專案實際建出的 cheat-engine-v0.3.1.apk，非示意值。

APK 就是一個 ZIP

把 .apk 改成 .zip 解開，就能看到它的全部內容。 裡面沒有魔法，只有一組約定好的檔案。有些是系統安裝時非要不可的， 沒有就裝不起來；有些是選配的。下面這張是本專案 APK 解開後的真實結構。

01

打包流程：原始碼怎麼變成這些檔案

上面每一個檔案，都是打包流程中某一隻工具的產物。左邊是你寫的原始碼（三種）， 中間是各自的編譯工具，它們產出的東西在右邊被打包、對齊、簽章，最後成為一支 APK。 gradle 只是總指揮，真正動手的是底下這幾隻。

02

每個檔案是誰

「必須」是指系統安裝或執行時非它不可；沒有就裝不起來、或裝起來也跑不動。 「視情況」與「選配」則看 App 有沒有用到對應的東西。

AndroidManifest.xml 必須
App 的身分申報表，二進位格式。package、sharedUserId、 權限、四大元件全在這。系統安裝時就讀完，程式還沒跑就知道它能做什麼。 3.7 KB
classes.dex
classes2.dex … 必須
你的 Java/Kotlin 程式碼，編成 Dalvik bytecode。一個 dex 有方法數上限（65536）， 超過就拆成 classes2、classes3…（本專案就有三個）。 合計 65 KB
resources.arsc 視情況
編譯過的資源索引表 —— 字串、顏色、版面、drawable 的 id 對應。 本專案全用程式化 View，所以它只有 40 B，近乎空的。 40 B
res/** 選配
圖檔、XML 版面、values/ 等資源本體。本專案沒有這個資料夾， 因為 UI 完全是 framework View 手寫的。一般 App 這裡通常很大。 （本專案無）
lib/<abi>/*.so 選配
原生共享庫，每個 CPU 架構一份。本專案是 Rust 編出的 libce_engine.so，三個 ABI —— 也是整支 APK 體積的來源（97.6%）。 純 Java App 沒有這層。 2.78 MB
assets/** 選配
原封不動打包的任意檔案（字型、資料檔、網頁…），程式用 AssetManager 讀。 不經 aapt2 編譯，放什麼是什麼。本專案沒用到。 （本專案無）
APK Signing Block 必須
v2 以後的簽章不是一個檔，而是夾在 zip 內容與中央目錄之間的一段資料， 對整包做雜湊。API 24+ 一律要求；未簽章的 APK 裝不上去。 v2 scheme
META-INF/** 自動
建置中繼資料（app-metadata.properties）。舊的 v1(JAR)簽章會在這裡放 MANIFEST.MF / *.SF / *.RSA， 但本專案只用 v2，所以這裡沒有簽章檔。 56 B
兩個看不見卻關鍵的東西

① Manifest 是二進位的。 你在 APK 裡看到的 AndroidManifest.xml 不是文字， 要用 aapt dump xmltree 或 apktool 才讀得回文字。

② v2 簽章不佔一個檔案格。 它是 zip 結構裡的一段特殊區塊，所以你解開 APK 在檔案清單裡 找不到它 —— 但少了它，系統直接拒裝。

03

一支 APK 至少要有什麼

剝到最小，能安裝並執行的 APK 只需要三樣，加上一個外部條件：

  • AndroidManifest.xml —— 沒有身分申報，系統不知道這是什麼，直接拒裝。
  • classes.dex —— 沒有程式碼就沒有能跑的東西（純資源包例外，但那不是可執行 App）。
  • APK Signing Block —— 未簽章一律裝不上，API 24+ 強制。
  • 外部條件：要能被啟動，Manifest 裡得有一個帶 LAUNCHER intent-filter 的 <activity> —— 否則裝得起來卻沒有桌面圖示。

其餘全是選配：沒有原生程式碼就沒有 lib/，沒有 XML 資源 resources.arsc 就近乎空、也沒有 res/ —— 本專案正是這個樣子。

所有檔名、位元組數與比例取自本專案實際建出的 cheat-engine-v0.3.1.apk （2,984,847 bytes，v2 簽章，三 ABI），以 unzip -l 與 apksigner verify 讀出，非示意值。打包工具鏈：cargo-ndk / aapt2 / javac / d8 / r8 / zipflinger / zipalign / apksigner，由 gradle 經 AGP 8.7.3 統籌， android/pack.sh 觸發並驗證。所有動畫為 SVG + SMIL，不依賴任何函式庫。 姊妹文件：architecture.html（共用行程架構）。
